# Оптимизация распаковки TGZ в PaxoInsight 6.0.1

Проверка выполнена 12 октября 2026 года на Windows x64 / CPython 3.14.7.

## Причина замедления

В версии 6.0 после каждого вложенного архива `_enforce_limits` заново обходил
весь рабочий каталог. Для 50 TGZ получалось 52 полных обхода: один после
основного архива, 50 после вложенных и один финальный. Чем больше файлов уже
распаковано, тем дороже каждый следующий проход.

Кроме того, TAR/TGZ сначала полностью читался через `getmembers()`, после чего
распаковка начиналась с начала. Это повторно декомпрессировало сжатые данные и
сохраняло весь индекс TAR в памяти. Поиск следующего уровня вложенности также
повторно обходил уже обработанные каталоги.

Версия 5.1.0 не выполняла полного пересчёта рабочего каталога после каждого
вложенного архива и распаковывала TAR без предварительного `getmembers()`.

## Изменение

- Начальный обход определяет файлы, объём и кандидатов на распаковку.
- После раскрытия контейнера проверяется только новый каталог.
- Суммарные счётчики обновляются на число и объём добавленных файлов.
- Удалённый вложенный архив освобождает соответствующую часть лимита.
- Каждый контейнер получает оставшийся лимит всего задания перед распаковкой.
- Новый уровень вложенности ищется только в добавленных каталогах.
- Финальный независимый обход подтверждает общий объём и количество файлов.
- TAR последовательно проверяет и извлекает записи, не загружая полный индекс.
- Для TAR/TGZ интерфейс сообщает количество файлов и объём с ограничением
  частоты обновлений до четырёх в секунду плюс финальное сообщение.

## Замеры

Сгенерирован ZIP с однотипными вложенными TGZ. Каждый TGZ содержит заданное
количество небольших текстовых файлов. Замер включает подготовку рабочей
области, SHA-256 входного ZIP и распаковку; генерация входных данных, очистка,
последующий анализ и сборка 7Z исключены.

| TGZ | Файлов на TGZ | Всего файлов | 6.0 | 6.0.1 | Ускорение |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 50 | 150 | 7 500 | 19,97 с | 7,36 с | 2,7 раза |
| 60 | 16 | 960 | 2,64 с | 0,80 с | 3,3 раза |
| 180 | 16 | 2 880 | 15,98 с | 2,78 с | 5,7 раза |

В 6.0.1 выполняются два полных обхода независимо от числа TGZ. Остальные
проверки затрагивают только новые каталоги. На синтетических данных весь набор
успешно распакован, число файлов и раскрытых контейнеров проверено.

Это отдельные локальные замеры, не гарантия времени обработки пользовательского
архива. Реальное время зависит от количества и размера файлов, глубины
вложенности, скорости диска и антивирусной проверки. Проблемный архив пользователя
в проверке не участвовал.

## Воспроизведение

Из корня проекта, с установленными зависимостями:

```powershell
$env:PYTHONPATH = "$PWD\src"
python .\build\benchmark_nested_tgz.py --counts 60 180
python .\build\benchmark_nested_tgz.py --counts 50 --files-per-tgz 150
```

Сценарий работает только со сгенерированными временными данными и проверяет
полноту результата. Для сравнения с 6.0 его можно запустить с импортом исходников
этой версии.

## Регрессионные проверки

Добавлены проверки массовой распаковки TGZ без повторных полных обходов,
последовательного чтения TAR, глубины вложенности и повторного анализа,
суммарных лимитов и освобождения лимита после удаления контейнера, отмены
операции, вывода прогресса и блокировки опасных путей, ссылок и специальных
TAR-записей. Portable self-test дополнительно раскрывает TGZ и включает его
содержимое в проверенный 7Z.
