Дата проверки: 20 октября 2026 года.

**Результат:** подготовлен новый Windows x64 portable на CPython 3.14.8.
Проверены исходники, совпадение критичных модулей внутри EXE с исходниками,
запуск GUI, функции обработки и защитные ограничения готового приложения.
Это техническая проверка обновления, не сертификация и не гарантия отсутствия
неизвестных уязвимостей.

## Что исправлено относительно аудита Standalone 6.1

| Находка | Результат проверки нового выпуска |
| --- | --- |
| S-01, большой промежуточный буфер ZIP/BZIP2 | На 16-МиБ ограниченном примере максимум декодера теперь 1 МиБ вместо прежних 16 МиБ; тест выполнен внутри нового EXE |
| S-02, неполные лимиты распаковки | В EXE включено текущее ядро с ограниченными writers, учётом каталогов и фактических байтов, резервом диска и отменой |
| S-03, пароль RAR в argv | В актуальном ядре пароль передаётся через stdin; регрессия проверяет отсутствие в argv. RAR3, RAR5 и RAR5 с шифрованными заголовками проверены с настоящим 7-Zip |
| S-04, дубли ZIP/TAR | Актуальное ядро отклоняет повторную запись вместо перезаписи; ZIP также проверен самотестом EXE |
| S-05, старые анализаторы/XML | Упакованы усиленные анализаторы, defusedxml и Expat 2.8.5; запрет DTD проверен в EXE |
| S-06, лимиты входной папки | Файлы, каталоги, фактические байты и резерв диска контролируются непосредственно при копировании; исходная папка сохраняется |
| S-07, цепочка поставки | Введены hash-lock установка, проверка runtime и встроенного кода, SBOM нативных файлов и файловый манифест; прочие ограничения ниже |

Дополнительно при настоящем RAR-тесте обнаружена Windows-ошибка: rarfile
пытался автоматически распаковать комментарий RAR3, ища свой внешний инструмент
в PATH. Теперь отдельный metadata-only адаптер не распаковывает комментарии;
извлечение выполняет только выбранный приложением 7-Zip. Глобальные объекты
rarfile не подменяются. Адаптер проверен для закреплённого rarfile 4.5 и требует
повторной проверки при смене версии зависимости.

Проверка сборки отклоняет Python ниже 3.14.8, другую minor-ветку,
не-CPython, 32-bit и free-threaded runtime. Сверяются 23 точные версии пакетов,
версия и полный SHA-256 Python DLL. Встроенный код 14 критичных модулей сравнивается
с текущими исходниками, включая новый RAR-адаптер. Старый `PaxoInsight`, Qt,
pip, setuptools и Web-серверные модули не должны попадать в runtime.

SBOM содержит 15 Python-библиотек, CPython и 125 фактических нативных
PE-файлов с SHA-256 и архитектурой. Манифест проверяет 259 файлов;
исключены только собственный манифест и верхнеуровневый SBOM, чтобы избежать
циклических хешей. Статически встроенные нативные подкомпоненты не объявляются
полностью описанными одним перечнем PE; необходимо учитывать upstream SBOMs.
Структура SBOM проверена по официальной JSON-схеме CycloneDX 1.6: ошибок нет.
Схемы получены из репозитория CycloneDX/specification; сайт cyclonedx.org
при прямой загрузке ответил HTTP 403.

## Что остаётся за рамками обновления

- EXE пока без Authenticode-подписи. Контрольные суммы не заменяют доверенную подпись.
- Нет отдельной песочницы/Windows Job Object с жёстким лимитом памяти.
  Неизвестные архивы не следует обрабатывать с правами администратора.
- Аварийное завершение может оставить расшифрованные временные файлы;
  гарантированного физического стирания нет.
- Внешний 7-Zip по-прежнему зависит от рабочего места; проверка минимальной
  версии и политика доверенного пути не реализованы. На тестовом ПК — 26.04.
- В поставляемом Python остаётся Tcl-зависимая zlib1.dll 1.3.2.
  Отмеченный прежним аудитом условный риск CVE-2026-85091 для non-blocking
  gzwrite/gzprintf не объявляется устранённым этим обновлением; достижимость
  этого API через приложение не подтверждена. Python zlib-ng — другая библиотека.
- Полный fuzzing нативных парсеров, длительная нагрузка больших реальных
  архивов, EDR/Defender и политики всех целевых машин не проверялись.

## Повторение сборки

При наличии стандартного Python 3.14.8 x64 в `C:\Paxo\.python3148`:

```powershell
cd C:\Paxo\PaxoInsightApp
pwsh -NoProfile -File .\build\setup_python314.ps1
pwsh -NoProfile -File .\build\build_windows.ps1
```

Скрипт не заменяет уже существующий финальный ZIP под тем же именем.
Пересборку следует выполнять с новым номером/именем артефакта либо после
явного сохранения предыдущего кандидата. Хеши конечного ZIP при новой сборке
могут отличаться из-за временных меток и идентификатора SBOM.
