# Структурное сопоставление Kotlin / JVM в PaxoInsight 6.1.2

Дата: 21 октября 2026 года. Статус: локальный portable-кандидат.

Этот документ описывает первоначальную 6.1.2. Начиная с 6.1.3 возвращены проценты
и устранена часть описанных ниже ограничений строк/конструкторов:
[актуальные дополнения и методика](KOTLIN_COVERAGE_6.1.3.md).

## Как работает

1. Для текущей рабочей области строится один индекс исходников и class-файлов.
2. Ограниченный лексический разбор Kotlin извлекает package, именованные классы,
   интерфейсы, objects, вложенные и companion-объявления, признаки пакетных
   функций/свойств и file-аннотации JvmName/JvmMultifileClass.
3. Бинарный парсер читает JVM constant pool, внутреннее имя, SourceFile,
   вид и версию kotlin.Metadata. Для multifile-частей читается связь с фасадом,
   для фасада — перечень частей. Классы не загружаются и не исполняются.
4. Сопоставление проверяет пакет, модуль, main/test-набор, известный вариант
   сборки и вид артефакта. Чужой модуль/тестовый класс не покрывает основной код.
5. Один результат используется интерфейсом, рекомендациями и отчётами;
   версии JVM также берутся из индекса. Повторный анализ строит новый индекс.

Временная рабочая область по-прежнему управляется общим workflow приложения;
сам Kotlin-индекс не создаёт базы данных и не хранит историю.

## Что означает статус

| Статус | Значение |
| --- | --- |
| ПОДТВЕРЖДЕНО | Для распознанных ожидаемых объявлений совпали структурные признаки и контекст |
| ЧАСТИЧНО | Есть подтверждённые объявления, но часть ожидаемых артефактов не подтверждена |
| ПРЕДПОЛОЖИТЕЛЬНО | Кандидат найден, но не хватает SourceFile, Kotlin Metadata или уверенного контекста |
| НЕОДНОЗНАЧНО | Найдены конкурирующие классы, варианты сборки или исходники |
| НЕ ОБНАРУЖЕН | Ожидаемое объявление не найдено среди проверенных данных |
| НЕ ПРОВЕРЕНО | Повреждённый файл, лимит, нераспознанный синтаксис/метаданные или оставшийся контейнер |
| НЕ ПРИМЕНИМО | Gradle/другой Kotlin-скрипт, известная не-JVM платформа, отсутствие самостоятельного объявления |

Синтетические классы, связанные по SourceFile/пакету/модулю, показываются отдельно
и не заменяют отсутствующий внешний/именованный класс. Класс без исходника —
информационная находка, не доказательство ошибки: в комплекте допустимы библиотеки.

## Примеры

- `Models.kt` содержит `User` и `Account`, но есть только `User.class`:
  **ЧАСТИЧНО**, с отдельной строкой ожидаемого `Account.class`.
- `App$Nested.class` не создаёт в отчёте вымышленный `App.class`.
- `moduleB/.../App.class` не подтверждает `moduleA/.../App.kt`.
- Класс из `build/classes/kotlin/test` не подтверждает `src/main/kotlin`.
- `@file:JvmName("Helpers")` меняет ожидаемый JVM-фасад пакетных объявлений.
- Для multifile нужны часть конкретного исходника и согласованный фасад.
- Два подходящих debug/release-варианта дают неоднозначность, а не случайный выбор.
- При нераспакованном JAR отсутствие класса не объявляется окончательно:
  сначала следует проверить содержимое контейнера с выбранными настройками.

`commonMain` не исключается автоматически: он может участвовать в JVM-компиляции.
`expect` требует отдельного сопоставления с `actual` и не считается самостоятельно
подтверждённым классом. Scripts `.kts` не смешиваются с обычными исходниками `.kt`.

## Ограничения и безопасность

- Это консервативный лексический анализатор, **не полный Kotlin AST/компилятор**.
  Сложные строковые шаблоны и конструкторы, вычисляемый JvmName и некоторые
  нестандартные file-аннотации приводят к понижению уверенности.
- Читается заголовок Kotlin Metadata, но не protobuf d1/d2 с полной моделью
  Kotlin-деклараций. SMAP, DEX/APK-байткод, Kotlin/Native и JS не разбираются.
- Не проверяется семантика методов и корректность JVM Code/StackMapTable.
  Структурное сопоставление не заменяет JVM-верификатор или SAST.
- Обфускация, shrinking, удаление debug-информации, нестандартные roots/Gradle
  source sets и перенесённые библиотеки могут оставить неопределённость.
  Автоматическое выполнение build.gradle/settings.gradle/pom.xml не производится.
- Размер одного `.class` ограничен 8 МиБ, `.kt` — 2 МиБ; суммарное чтение
  Kotlin/JVM в одном анализе — 512 МиБ. Ограничены токены, глубина и число
  элементов аннотаций. На превышении выводится непроверенный результат, не успех.
- Совпадение SourceFile и Metadata **не доказывает**, что байткод собран именно
  из переданных байтов исходника. Для этого нужна доверенная сборка/манифест.
- Безопасность распаковки и оставшиеся эксплуатационные ограничения Standalone
  сохраняются: см. аудит и отчёт обновления 3.14.8. Не запускайте неизвестные
  материалы с правами администратора.

## Проверка

- В модульных тестах используются локально сгенерированные class-структуры:
  несколько объявлений, main/test, модули, nested/companion, JvmName/multifile,
  неоднозначность, повреждение, лимиты и отмена. Удаление устаревших результатов
  проверяется сквозным повторным анализом.
- Прочитаны все **995 class-файлов** официального Kotlin stdlib 2.4.21:
  поддержанные виды Metadata 1–5 и классы без Metadata, ошибок разбора не было.
  JAR не запускался. Реальные `Pair.class`, `Triple.class`, `TuplesKt.class`
  успешно сопоставлены с официальным `Tuples.kt`.
- Реальные Tk-виджеты проверены в скрытом окне: 7 колонок, частичный/отсутствующий
  класс, реальные пути и исчезновение устаревших результатов после rescan.
- Самотест готового EXE включает Kotlin-файл с двумя объявлениями и одним
  class-файлом; ожидает именно частичный комплект.

Материалы: [проверка и хеши JAR](kotlin-analysis-2026-10-21/kotlin-verification.json),
[пример HTML-отчёта](kotlin-analysis-2026-10-21/kotlin-example-partial.html),
[регрессионные тесты](kotlin-analysis-2026-10-21/tests-source.txt).

Тестовые JAR загружены по HTTPS из Maven Central и не входят в portable.
Для них записаны локальные SHA-256 и проверена ZIP CRC. URL `.jar.sha256`
для этого артефакта вернул 404; независимая криптографическая подпись поставщика
этой проверкой не подтверждалась. Исходники stdlib имеют Apache-2.0-лицензию.

## Воспроизведение и сборка

```powershell
cd C:\Paxo\PaxoInsightApp
C:\Paxo\.venv3148\Scripts\python.exe -m unittest discover -s tests -p test_kotlin_structural.py -v
C:\Paxo\.venv3148\Scripts\python.exe build\verify_kotlin_analysis.py --fixtures build\kotlin-fixtures --output docs\kotlin-analysis-2026-10-21
pwsh -NoProfile -File build\build_windows.ps1 -BuildVariant kotlin-6.1.2
```

Сборка идёт в отдельные `build/kotlin-6.1.2` и `dist/kotlin-6.1.2`.
Старые portable ZIP и папка сборки 6.1.1 не заменяются.
