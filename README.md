# PaxoInsight 6.0

PaxoInsight — самостоятельное настольное Windows-приложение для безопасной
распаковки, предварительного анализа и повторной упаковки программных
артефактов в проверенный архив 7Z.

Приложение обрабатывает одно текущее задание за раз. Оно не является частью
PatrolDeck, не использует базу данных и не хранит историю обработанных архивов.
Пароли существуют только в памяти во время распаковки.

## Что нового в 6.0

- обновлён интерфейс и внедрён фирменный дизайн-код PaxoInsight;
- добавлены новые форматы архивов и JAR-подобных контейнеров;
- переработан механизм работы с текущим архивом или папкой;
- добавлены повторный анализ и изменение параметров после первого прохода;
- добавлена сборка результата в новый проверяемый архив 7Z;
- добавлена заметная классификация RPM, DEB, установщиков, исполняемых файлов,
  библиотек, сторонних архивов и JAR-подобных контейнеров;
- добавлено отдельное обнаружение Kotlin и сопоставление `.kt`/`.kts` с
  соответствующими `.class`;
- добавлен сохраняемый автономный HTML-отчёт по Kotlin;
- добавлены защита распаковки, лимиты ресурсов и SBOM;
- выполнен переход на стабильный 64-разрядный CPython 3.14;
- исключена зависимость от Qt/PySide и связанная с ней загрузка `QtCore.dll`.

## Рабочий процесс

1. Пользователь выбирает или перетаскивает архив либо папку.
2. PaxoInsight создаёт защищённую временную рабочую область.
3. Архив распаковывается, а содержимое папки копируется без изменения оригинала.
4. Для зашифрованного архива пароль запрашивается в интерфейсе — до пяти попыток.
5. Основной и вложенные архивы раскрываются с учётом выбранных настроек.
6. Успешно распакованные вложенные архивы заменяются их содержимым.
7. Выполняется анализ расширений, контейнеров, исполняемых пакетов и Kotlin.
8. После анализа настройки можно изменить и запустить повторный анализ.
9. Команда **«Собрать и проверить 7Z»** создаёт новый архив без лишнего верхнего
   каталога, проверяет его и рассчитывает SHA-256.
10. При переходе к следующему заданию временная рабочая область очищается.

Удаление исходного архива включено по умолчанию, как в классическом
PaxoInsight. Оно происходит только после полностью успешного анализа. Исходная
папка никогда не удаляется и не изменяется. Вложенный архив удаляется только
после успешного раскрытия; при ошибке или отмене ввода пароля он остаётся в
рабочем наборе.

## Анализ и отчётность

Раздел **«Находки»** использует текстовые уровни и семантические цвета: от
критического красного до информационного серо-синего. Вкладка
**«Контроль файлов»** показывает точные пути к следующим объектам:

- RPM, DEB, MSI/MSIX, APPX, PKG и другим устанавливаемым пакетам;
- EXE, DLL, SYS, SO и другим исполняемым файлам или библиотекам;
- JAR-подобным прикладным контейнерам;
- сторонним архивам, образам и пакетам;
- исходным файлам Kotlin `.kt` и `.kts`.

Вкладка **«Kotlin ↔ .class»** сопоставляет исходники с результатами компиляции.
Для каждого `.kt` проверяются `Name.class`, `NameKt.class` и вложенные
`Name$*.class` с учётом типовых каталогов Gradle. Отдельно показываются:

- основной и тестовый Kotlin-код без соответствующего `.class`;
- Kotlin-подобные классы без найденного `.kt`;
- исключённые сценарии `*.gradle.kts`.

Через меню **«Отчёт»** результат можно сохранить как автономную HTML-страницу.
Отчёт не использует внешние скрипты или сетевые ресурсы. При включённой
настройке отчёты TXT, JSON и `PaxoInsight_Kotlin_Report.html` добавляются в
итоговый 7Z.

## Поддерживаемые форматы

| Категория | Форматы |
| --- | --- |
| Основные архивы | ZIP, 7Z, RAR |
| TAR-контейнеры | TAR, TAR.GZ, TGZ, TAR.BZ2, TBZ2, TAR.XZ, TXZ |
| Потоковое сжатие | GZ |
| Java/Jakarta и мобильные контейнеры | JAR, WAR, EAR, BAR, SAR, AAR, AAB, APK, IPA, EBA, CBA, ESA |
| IBM App Connect | APPZIP, LIBZIP, SHLIBZIP, APPDOMAINZIP, XSDZIP |
| Входные каталоги | Обычная папка с файлами и вложенными архивами |

Автоматическое раскрытие JAR-подобных контейнеров внутри другого архива
управляется настройкой **«Распаковывать ZIP/JAR-контейнеры»**. Тип проверяется
по содержимому, а не только по расширению.

RAR распаковывается установленной консольной версией 7-Zip. Приложение ищет
`7z.exe` рядом с собой, в `PATH`, стандартных каталогах Windows и реестре. Для
нестандартной установки можно задать `PAXOINSIGHT_7ZIP` или прежнюю
`PAXO_7Z_PATH`.

Расширение `.rar` может означать обычный RAR или Java/Jakarta Resource Adapter
Archive. PaxoInsight различает их по сигнатуре: обычный RAR передаётся 7-Zip,
а Resource Adapter Archive обрабатывается как ZIP-контейнер.

## Безопасность

- блокируется выход путей за пределы каталога распаковки;
- символические и аппаратные ссылки не извлекаются;
- действуют лимиты количества файлов и распакованного объёма;
- выходной 7Z сначала создаётся как временный файл;
- существующий результат заменяется только после успешной проверки нового 7Z;
- очищается только рабочая папка с внутренним маркером PaxoInsight;
- при ошибке анализа исходный архив не удаляется;
- пароли не записываются в журнал, отчёты или конфигурацию;
- зависимости зафиксированы lock-файлами;
- состав компонентов опубликован в `SBOM.cdx.json` в формате CycloneDX.

## Дизайн-код PaxoInsight

### Концепция

Визуальный язык передаёт три свойства продукта: **аналитичность, безопасность
и прозрачность анализа**. PaxoInsight выглядит как спокойный корпоративный
DevSecOps-инструмент, без «хакерских» клише и избыточного футуризма.

Логотип объединяет глаз, технологический шестиугольник и линии печатной платы:

- глаз — анализ и выявление скрытых признаков;
- шестиугольник — структура и защищённый контур;
- линии платы — исходный код, зависимости и программные артефакты.

Основная логика продукта и интерфейса:

> **Код → Анализ → Контекст → Риск → Решение**

### Цветовая система

| Токен | Назначение | HEX |
| --- | --- | --- |
| Primary Navy | глубокий фирменный синий | `#0B2A5B` |
| Brand Blue | основные действия и навигация | `#0098FF` |
| Accent Cyan | технологический акцент | `#00D4FF` |
| Text Primary | основной текст | `#0F172A` |
| Text Secondary | вторичный текст | `#64748B` |
| Border | границы и разделители | `#E2E8F0` |
| Surface | нейтральные поверхности | `#F8FAFC` |
| Background | основной фон и карточки | `#FFFFFF` |

Семантические статусы:

| Статус | Цвет | HEX |
| --- | --- | --- |
| Success | зелёный | `#22C55E` |
| Warning | оранжевый | `#F59E0B` |
| Danger / Critical | красный | `#EF4444` |
| Information / Scanning | синий | `#0098FF` |

Фирменный градиент `#0B2A5B → #0098FF → #00D4FF` предназначен преимущественно
для логотипа, крупных акцентов и визуализации данных. В рабочих элементах
интерфейса он используется умеренно.

### Типографика

Основной шрифт — **Inter**. В настольном приложении используется системный
резерв **Segoe UI**, если Inter отсутствует. Для путей и технических данных
предпочтителен **JetBrains Mono**, резервный вариант — **Consolas**.

| Элемент | Размер | Начертание |
| --- | ---: | --- |
| H1 | 32 px | Bold |
| H2 | 24 px | SemiBold |
| H3 | 20 px | SemiBold |
| H4 | 16 px | SemiBold |
| Основной текст | 16 px | Regular |
| Вторичный текст | 14 px | Regular |
| Caption | 12 px | Regular |

Числа метрик и количество найденных объектов выделяются SemiBold или Bold.

### Сетка, отступы и поверхности

- базовый шаг: `4 px`;
- шкала: `4 / 8 / 16 / 24 / 32 / 48 / 64 px`;
- кнопки: `8–12 px` по вертикали и `16–20 px` по горизонтали;
- внутренний отступ карточек: `16–24 px`;
- расстояние между карточками: `16–24 px`;
- расстояние между крупными разделами: `32–48 px`;
- максимальная ширина desktop-контейнера: `1440 px`;
- рекомендуемая сетка: 12 колонок;
- радиусы: `4 px` для тегов, `8 px` для кнопок и карточек, `12 px` для
  крупных панелей и модальных окон;
- тень карточки: `0 4px 16px rgba(15, 23, 42, 0.08)`;
- для рабочих таблиц предпочтительна тонкая граница `#E2E8F0`.

### Кнопки и приоритет действий

- **Primary:** `#0098FF`, белый текст — одно главное действие на экране;
- **Secondary:** белый фон, синяя рамка и синий текст;
- **Ghost:** без рамки или с нейтральной светлой подложкой;
- **Danger:** только для потенциально разрушительных действий.

До окончания анализа главным действием является запуск анализа. После успешного
прохода визуальный приоритет переходит к сборке и проверке 7Z.

### Статусы и уровни внимания

Цвет всегда сопровождается текстом, а по возможности — иконкой:

- зелёный — **Завершено / Безопасно**;
- синий — **Сканируется / Анализируется**;
- оранжевый — **Требует внимания**;
- красный — **Критично**;
- серый — **Не определено / Не анализировалось**.

Уровни анализа: **Критический**, **Высокий**, **Средний**, **Низкий** и
**Информационный**. Итоговая оценка никогда не должна отображаться только
цветом — рядом требуется название уровня и краткая причина.

Файловые категории имеют отдельные подложки: пакеты и установщики — красные,
исполняемые файлы — светло-красные, JAR-подобные контейнеры — янтарные,
Kotlin — фиолетовый, архивы — синие, сторонние архивы — нейтральные.

### Карточки, таблицы и код

Карточка анализа должна показывать источник, версию, состояние, количество
находок и итоговый уровень внимания. Результаты представляются аналитическими
таблицами с рекомендуемой структурой:

`Файл / Артефакт | Тип | Категория | Уровень | Статус | Источник | Действия`

Код и пути отображаются моноширинным шрифтом. Подсвечивается конкретная
проблемная строка или объект, рядом выводятся уровень и понятное объяснение.

### Иконография и навигация

Иконки должны быть линейными, простыми и геометричными, с толщиной линии около
`2 px`. Базовые образы: eye, shield, code brackets, package/cube, dependency
graph, search, chart, report и warning triangle. Тяжёлые filled-иконки не
смешиваются с outline-набором.

Для будущей расширенной версии допускается навигация:
**Проекты → Анализы → Артефакты → Результаты → Отчёты → Настройки**.
Корпоративное расширение может включать интеграции, API и администрирование, но
текущая standalone-версия не хранит историю и не использует базу данных.

### Визуализация и тёмная тема

Графики применяются только когда помогают принять решение: распределение
уровней, типы артефактов, пригодность поставки и зависимости. Трёхмерные
диаграммы и декоративный визуальный шум не используются.

Рекомендуемая палитра необязательной тёмной темы:

- фон: `#081A33` или `#0B1F3A`;
- карточки: `#102A4C`;
- основной текст: `#F8FAFC`;
- вторичный текст: `#94A3B8`;
- Brand Blue и Accent Cyan сохраняются без изменения.

### Тон бренда

PaxoInsight — **технологичный, строгий, спокойный, интеллектуальный и
уверенный** продукт. Не используются зелёный «матричный» код, черепа,
агрессивный неон и бессистемная терминальная эстетика.

## Запуск из исходников

Требуется стандартный 64-разрядный CPython 3.14, не free-threaded, и 7-Zip для
RAR и внешнего создания 7Z.

```powershell
python -m pip install -e .
python -m paxoinsight
```

Зафиксированные версии библиотек для воспроизводимой сборки находятся в
`requirements-runtime.lock.txt` и `requirements-build.lock.txt`. Старые
расширения CPython 3.12 из версии 5.1 не добавляются в пути импорта.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

## Portable-сборка

```powershell
powershell -ExecutionPolicy Bypass -File .\build\setup_python314.ps1
powershell -ExecutionPolicy Bypass -File .\build\build_windows.ps1
```

По умолчанию используется `C:\Paxo\.venv314\Scripts\python.exe`. Другой
CPython 3.14 можно указать переменной `PAXOINSIGHT_BUILD_PYTHON`.

Сборка создаётся в `dist\python314\PaxoInsight`, а готовый пакет —
`dist\PaxoInsight_v6.0_Python314_Portable.zip`. Это one-folder-сборка:
`PaxoInsight.exe` должен находиться рядом с каталогом `_internal`.

Готовые пакеты публикуются отдельно на странице
[GitHub Releases](https://github.com/DiamondGnom/PaxoInsight/releases) и не
добавляются в историю исходного кода.
